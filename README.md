# digest-site — публичен сайт с дайджестите

Новини, дневен дайджест със събития, Подари Време, RADAR действия,
табло с коли и AI план за учене. Всичко, което Muse генерира като HTML,
се качва тук автоматично.

Адрес: https://frashev.github.io/digest-site/

Дизайн v2 (от 23.11.2026, ~09:00): МНОГОСТРАНИЧЕН — 11 страници:
`index.html` (начало: hero + днес + решетка с разделите), `news.html`,
`events.html`, `week.html`, `vreme.html` (страницата е `vreme.html`,
защото `weather.html` е файлът с прогнозата), `podari.html`,
`radar.html`, `cars.html`, `aiplan.html`, `subs.html`, `search.html`
(глобално търсене през `search.json`). Mobile-first, топла хартия
(#FBF9F3), един тухлен акцент (#9C493D), лепкаво меню с къси етикети —
активната страница е маркирана, менюто се скролва до нея, fade маска
вдясно показва, че има още. Scrollspy е махнат (активната страница се
знае при генерирането). Никой не отваря отделни HTML файлове — всичко
се чете НА СТРАНИЦАТА: малките файлове без скриптове (седмица, време,
абонаменти, AI план) се вграждат директно, а изданията (новини/дайджест)
и файловете със скриптове (Подари Време, RADAR, Коли) се показват във
вграден iframe с автоматична височина — родителят мери долния ръб на
последния видим елемент (не scrollHeight, за да няма празна ивица под
съдържанието). Всяко издание/дайджест има дълбок линк (`news.html#ed-…`,
`events.html#dg-…`) — отваря се при зареждане. Филтрите на дайджеста
(дни, категории) работят вътре в него. RSS: `feed.xml` (последните 20
новини). Фавикон: `favicon.svg` + ICO + PNG комплект (`build-favicon.py`)
— теракота квадрат с бяло „Д". Изданията са престилизирани в топлата
палитра: `restyle-editions.py` + `fix-digest-style.py` (топъл вариант на
актуалния стил от `build-digest-2026-11-22.py`; еднократните файлове
`digest-tonight-*` и `events-tonight-*` имат собствен стил и не се пипат).

Файлове в тази папка (източници — същите имена в `~/workspace/scripts/site/`):
- `build-index.py` — генерира 11 страници + `search.json` + `feed.xml`
  (сканира папката, класира изданията, вгражда малките файлове,
  останалото — iframe). Генерираните страници се изключват от
  сканирането (списък `GENERATED`), за да не се вземат за съдържание.
- `build-favicon.py` — рисува комплекта икони (PIL + DejaVu Bold).
- `build-weather.py` — прогноза за София (Open-Meteo, wttr.in резерва).
- `publish.ps1` — генерира страниците, commit-ва и push-ва.
- `site-sync.py` — НЕ е тук, а при Muse; той копира файловете насам.
  В `SOURCES` са и еднократните файлове със събития
  (`events-tonight-2026-11-03-bar-club.html`,
  `events-2026-11-05-12-full.html`) — излизат в „Още" на страницата
  Събития; `build-index.py` НЕ се синхронизира оттук — качва се ръчно
  с `scp` при промяна.

Как работи:
- Muse генерира HTML файловете в своя workspace.
- `site-sync.py` (на Muse, на всеки час) копира новите/променените
  файлове в тази папка през SSH и пуска `publish.ps1`.
- `publish.ps1` (на този компютър) генерира `index.html` през
  `build-index.py`, commit-ва промените и ги push-ва към GitHub.
- GitHub Pages сервира сайта. Push-ът става от този компютър през
  SSH ключ (`~/.ssh/id_rsa_github`), затова не иска одобрения
  в чата на Muse и не иска `gh auth login`.
