# Security (digest-site)

Checklist for operators and reviewers. Scope: static GitHub Pages site generated by `build-index.py` and published via `publish.ps1`.

## XSS mitigation

- [x] Global search (`search.html`): result titles, metadata, and snippets are rendered with `document.createElement` and `textContent`, not `innerHTML`.
- [x] Search result links: client-side `safeResultHref()` accepts only relative `.html` paths and in-page `#fragments`; rejects `javascript:`, `data:`, and other external schemes.
- [x] FAB section menu (floating nav): built with DOM APIs and `textContent`; fragment targets validated with `safeFragId()`.
- [ ] Edition HTML files (`novini-*.html`, etc.) are produced upstream by Muse; review those pipelines separately if they accept untrusted input.

## Publish allowlist

- [x] `publish.ps1` stages only explicit site artifacts (generated pages, icons, manifest, content globs)—not `git add -A`.
- Manual commits for `build-index.py`, workflows, or `SECURITY.md` are outside the publish script.

## Secret scanning

- [x] GitHub Actions runs [Gitleaks](https://github.com/gitleaks/gitleaks) on push/PR.
- Default config scans the **commit diff** on PRs and new commits; tune `.gitleaks.toml` if historical findings need suppressions.

## GitHub Pages headers

- [x] **Meta CSP** and `referrer` are injected in the HTML shell in `build-index.py` (`default-src 'self'`, inline script/style allowed for this static inline bundle).
- **HTTP response headers** (e.g. `Content-Security-Policy`, `X-Frame-Options`, HSTS) are **not** configurable on standard GitHub Pages for this repo. Use meta tags for policy hints; for strict headers, put a reverse proxy or Cloudflare in front of the Pages URL.

### Platform limits (expected)

GitHub Pages does not emit `Content-Security-Policy`, `Strict-Transport-Security`, or `X-Frame-Options` as HTTP response headers for this static site—only policies embedded in the HTML (e.g. meta CSP from `build-index.py`) apply. That meta CSP includes `'unsafe-inline'` for the bundled inline script and styles, so it is a secondary, softer layer; primary XSS control remains DOM rendering with `textContent` and validated hrefs (see **XSS mitigation** above). These constraints are normal for static Pages hosting and are not a gap in the DOM-based search/FAB hardening from PR #1.

## What the 2026-11-25 audit did **not** cover

- Upstream Muse content generation and SSH sync (`site-sync.py`).
- Third-party links inside news articles (`target="_blank"` on external sites).
- Supply-chain of Python dependencies on the publish PC (`publish.ps1` runs local `python`).
- DDoS, rate limiting, or authentication (public static site).
- Integrity of `events-registry.json` (gitignored local file on the publisher).
